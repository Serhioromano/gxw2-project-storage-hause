# План разработки программы ПЛК — система автоматизации камеры овощехранилища

**Объект:** камера хранения картофеля (520–720 т), г. Алма-Ата
**ПЛК:** COOLMAY-L02 (совместим с FX3G)
**Среда:** GX Works 2 (IEC 61131-3, Structured Text)
**HMI:** COOLMAY-TK8100
**Ревизия плана:** v1.0
**Дата:** 2026-08-12

---

## 1. Цель

Разработать единую программу ПЛК для 10 однотипных камер хранения, реализующую:
- автоматический режим (рециркуляция + периодическая аспирация);
- режим «Продувка» (ручной, ПЛК мониторит и держит клапаны);
- режим «Выключено» (только мониторинг);
- ручную аспирацию по таймеру с HMI;
- 28 тревог с задержками, защёлками и PUSH-уведомлениями;
- световую сигнализацию (колонна 🔴/🟢);
- полный мониторинг на панели TK8100.

Программа пишется один раз и заливается в 10 шкафов (ШУК.260726) без изменений —
все отличия между камерами (если появятся) выносятся в настройки HMI.

## 4. Решения по уточнениям (внесены в ТЗ v1.1)

| № | Вопрос | Решение |
|---|---|---|
| 1 | Обратная связь разгонных вентиляторов | Разгонные — 220 В, тепловой защиты нет → **обратной связи нет**, тревог «пускатель разгонного» нет. Контроль только по факту выдачи DO |
| 2 | Реле контроля фаз | Добавлено на схему: **DI X02** (в карту адресов внесено) |
| 3 | Увлажнитель | Один вход X21 «работает / не работает» (питание и процесс не разделяются) |
| 4 | Y00 «Остановить холод» | **1 = запрет охлаждения, 0 = разрешение.** Контакт в покое разомкнут → при обесточивании ПЛК холод не блокируется. Y00 = 1 только во время аспирации |
| 5 | Порог обрыва 4-20 мА | ≥ 32720 относится **только к host** (D8032/D8033). Модуль L02-RTD контроля обрыва не имеет и выдаёт **готовую температуру** щупов (R23700–R23703) |
| 6 | Продувка | Сигнал «Продувка» (X01) идёт в ПЛК, чтобы ПЛК сам ставил нужную комбинацию клапанов без изменения схемы: рециркуляция открыта, приток/сброс закрыты. Вентиляторы — вручную |

## 5. Таблица тревог (28 шт.)

Нумерация AlarmManager: `0…27`. Единица задержки = **100 мс**. `AM_ALARMS_NUM := 28`.

| ID | Тревога | Кол-во | Задержка | Защёлка | Severity | xLock | Примечание |
|---|---|---|---|---|---|---|---|
| 0 | Реле контроля фаз (X02) | 1 | 0 с (0) | нет | Error | **да** | останов всех двигателей |
| 1–6 | Клапан не открылся | 6 | 60 с (600) | нет | Warning | нет | снимется при открытии |
| 7–12 | Нет потока, напорный вент. | 6 | 30 с (300) | нет | Error | нет | снимется при восстановлении |
| 13–18 | Пускатель напорного не замкнулся | 6 | 3 с (30) | **да** | Error | нет | ручной сброс |
| 19–22 | Обрыв Pt100 (щупы 1–4) | 4 | 3 с (30) | нет | Warning | нет | модуль L02-RTD без контроля обрыва — детекция по значению ≤ −190 °C (см. §9.1) |
| 23 | Обрыв датчика улицы (0-10 В) | 1 | 3 с (30) | нет | Warning | нет | ErrWire от SCALE_AI (g_xErrTout, M552) |
| 24–25 | Обрыв 4-20 мА ПВТ110 (t°, влажн.) | 2 | 3 с (30) | нет | Warning | нет | сырое значение ≥ 32720, только host (D8032/D8033) |
| 26 | Температура продукта выше макс. | 1 | 5 с (50) | нет | Error | нет | любой из 4 щупов, предел из настроек |
| 27 | Влажность ниже минимума | 1 | 5 с (50) | нет | Error | нет | предел из настроек |

- Защёлка только у пускателей напорных (13–18) → сброс через экран тревог HMI (AM_RESET).
- Автосброс: по ТЗ «Выключен» по умолчанию (настройка на HMI + задержка 60 мин) — реализуем через таймер на HMI-настройке; при значении «Включен» AM_RESET выполняется автоматически после задержки.
- Красная колонна: мигает при любой активной тревоге (AM_HAS_ALARM).
- Уведомления PUSH (мобильный мониторинг) — вне ПЛК (см. §9.5).

## 6. Алгоритмы управления

### 6.1 Режимы (приоритет по переключателю)

| X00 (Авто) | X01 (Продувка) | Режим |
|---|---|---|
| 0 | 0 | Выключено |
| 1 | x | Авто |
| x | 1 | Продувка (приоритет) |

Спорное состояние (оба = 1) → считать «Продувка» (безопаснее, ничего не запускаем автоматически).

### 6.2 Режим «Выключено»
- Все DO в 0 (вентиляторы, клапаны — пружина закроет, подогрев).
- Y00 = 0 — охладитель не блокируется (работает от собственного термостата).
- Колонна: оба off. Мониторинг работает, тревоги датчиков активны.

### 6.3 Режим «Продувка»
- Клапаны: рециркуляция открыта (Y30, Y31), приток/сброс закрыты (Y24–Y29 = 0).
- Вентиляторы: **не управляются ПЛК** (оператор — вручную).
- Колонна: 🔴 горит постоянно, 🟢 горит постоянно.

### 6.4 Режим «Авто» — конечный автомат

Состояния:
1. **РЕЦИРКУЛЯЦИЯ** (основное)
   - Клапаны: рециркуляция открыта, приток/сброс закрыты.
   - Y00 = 0 (холод разрешён).
   - Охладитель вкл (X20) → все 10 вентиляторов вкл; X20 = 0 → все стоп.
   - Отсчёт времени до аспирации (по интенсивности).
2. **ПЕРЕХОД → АСПИРАЦИЯ** (при таймере рециркуляции = 0):
   - Проверка t улицы: 3 °C ≤ t ≤ 25 °C (настройки). Нет → сброс таймера, остаёмся в рециркуляции (пропуск цикла).
   - Y00 = 1 (остановить холод) — холодильник не включится.
   - Если t улицы < 5 °C → подогрев заслонок приток/сброс (Y20–Y23) на 3 мин.
   - Клапаны: открыть приток/сброс (Y24–Y29 = 1), закрыть рециркуляцию (Y30, Y31 = 0).
   - Пауза 30 с (задержка пуска).
   - Все 10 вентиляторов вкл.
3. **АСПИРАЦИЯ** (5 мин по таймеру):
   - Вентиляторы работают, Y00 = 1 (холод остановлен).
4. **ПЕРЕХОД → РЕЦИРКУЛЯЦИЯ**:
   - Клапаны: закрыть приток/сброс, открыть рециркуляцию.
   - Y00 = 0 (холод разрешён).
   - Сброс таймеров, цикл повторяется.

Интенсивность (настройка HMI): Слабо = 1200 мин, Нормально = 600 мин, Интенсивно = 300 мин рециркуляции; аспирация всегда 5 мин.

> Ограничение: вентиляторы во время аспирации работают независимо от X20 (охладитель заблокирован). Учесть при контроле потока: тревоги «нет потока» должны сниматься после задержки 30 с от пуска (условие «вентилятор запущен и прошла задержка»).

### 6.5 Ручная аспирация (HMI)
- Кнопка + время (мин) на HMI.
- В режиме «Авто»: прерывает цикл, выполняет последовательность аспирации на заданное время, затем возврат в рециркуляцию.
- В режиме «Продувка»/«Выключено»: разрешить? По ТЗ — «возврат в предыдущий режим», т.е. допустима из любого режима. Реализовать через тот же автомат (приоритет над регулярной аспирацией).

### 6.6 Контроль исполнительных механизмов
- **Клапаны:** по концевикам. Тревога «не открылся» если DO=1 (команда открыть), а концевик не сработал через 60 с. Клапан без привода на закрытие — закрытие по пружине, концевика «закрыт» нет — контролируем только открытие.
- **Напорные вентиляторы:** тревога «нет потока» если DO=1, реле давления не сработало через 30 с (с момента пуска). Тревога «пускатель» если DO=1, а обратной связи нет через 3 с.
- **Разгонные вентиляторы:** 220 В, без тепловой защиты — обратной связи нет, контролируются только по факту выдачи DO (тревог пускателей/потока по ним нет).
- **Охладитель:** X20 (в работе) — статус на HMI; блокировка Y00.
- **Увлажнитель:** X21 — статус на HMI, тревог по нему нет.

### 6.7 Световая колонна (сводно)

| Режим/событие | 🔴 | 🟢 |
|---|---|---|
| Выключено | off | off |
| Продувка | горит | горит |
| Авто, рециркуляция | мигает при тревогах | горит |
| Авто, аспирация | мигает при тревогах | мигает |
| Тревоги (любой режим) | мигает | — |

Мигание: 0.5 с / 0.5 с (таймер 500 мс, TimeControl).

## 7. Структура программы (POUs)

Проект в GX Works 2, одна программа `MAIN` + функции/ФБ. Код — в папке `ПЛК/` (по одному файлу на POU для версионирования, вставлять в GXW вручную по этапам).

| Файл | POU | Назначение |
|---|---|---|
| `ПЛК/src/PRG_MAIN.st` | MAIN | **бизнес-логика**: код бывших ФБ `FB_PROCESS` + `FB_ACTUATORS` вставлен напрямую и объединён (конечный автомат Авто + приводы) |
| `ПЛК/src/PRG_ROUTINE.st` | PRG_ROUTINE | **рутины**: код бывших ФБ `FB_IO` + `FB_ALARMS` вставлен напрямую (AI → FLT10 → REAL `AI_*`, тревоги) + вызов ФБ `FB_LIGHT` |
| `ПЛК/src/FLT10.st` | FLT10 (FUN) | конвертация INT → REAL (масштаб ×10 сохраняется, деление на 10 — на HMI); вызывается в PRG_ROUTINE |
| `ПЛК/src/PRG_INIT.st` | INIT (по M8002) | настройки по умолчанию, AM_INIT ×28, (задел) Modbus |
| `ПЛК/src/FB_LIGHT.st` | FB_LIGHT | выбор режима, световая колонна (единственный ФБ проекта) |

### Регистры (предварительная карта — уточнить на этапе 2)
- `D0–D15` — **масштабированные значения датчиков, REAL** (метки `AI_*` из IO.csv; по 2 слова на значение, функция FLT10):
  D0–D1 = t улицы, D2–D3 = t камеры, D4–D5 = влажность, D6–D13 = t продукта 1–4, D14–D15 = средняя t. Числовое значение в масштабе ×10 сохраняется (деление на 10 — на панели HMI); логика сравнивает с порогами ×10 как раньше.
- `D500–D515` — **настройки HMI** (интенсивность, пределы, задержки; D511–D515 — коррекция датчиков; энергонезависимые).
  Флаг «автосброс тревог» — `g_xAutoReset` (M525).
- `D520–D523` — IP ПЛК (энергонезависимые).
- `D530–D535` — **статусы для HMI** (режим, таймеры обратного отсчёта).
- `D550–D551` — упакованные тревоги (AM_PACK, 2 регистра на 28 шт.).
- `D600–D800` — буфер Modbus (задел, если понадобится диспетчеризация).
- `M500–M525, M550–M552` — команды/флаги (энергонезависимые): M500–M505 напорные вент., M506–M509 разгонные, M510–M515 клапаны, M516–M519 подогрев, M520–M524 команды/кнопки, M525 автосброс, M550–M552 сводные флаги.
- Область AlarmManager (1400 D / 2000 M) — за пределами пользовательского диапазона.

## 9. Открытые вопросы и риски

1. **L02-RTD:** какое значение выдаёт модуль при обрыве Pt100 (для детекции тревоги 5.1–5.4) и в каких единицах выдаёт температуру (°C или °C×10) — проверить на стенде (этап 3).
2. Подтвердить у электриков физическую полярность контакта Y00 (в покое разомкнут = разрешение охлаждения).
3. Push-уведомления: реализация вне ПЛК (шлюз/облако), ПЛК отдаёт состояние через Modbus TCP или встроенный Ethernet — уточнить формат интеграции.
4. Размер программы: следить за шагами (лимит 32k), информационные сигналы — через события AM_EVENT вместо алармов.
5. Концевики клапанов: проверяем только «открыт»; «закрыт» — по пружине, без контроля.
6. Охладитель в режиме «Выключено» не блокируется (Y00 = 0) — работает от собственного термостата; согласовано с заказчиком (fail-safe в сторону разрешения).

Ключевые решения, принятые при генерации (сверить на стенде):
- полярности НЗ-входов: «не открыт»/«нет потока» = X=1 (вопросы 1.2/1.3);
- ручная аспирация из «Продувки»/«Выключено» — ПЛК временно управляет вентиляторами;
- тики M8013 (1 с) и M8014 (1 мин); при отсутствии M8014 — замена на TON 60 с;
- Y00 = 1 только в состояниях 200/300 (подготовка/аспирация);
- коррекция Pt100 вынесена в настройки HMI (D111–D115).

Изменения по результатам ревью (2026-08-12):
- HMI-блок удалён (TK8100 читает X/Y/M напрямую); дублирующие D-статусы
  (охладитель/увлажнитель/битовые слова/сырые 4-20 мА) убраны, обрыв 4-20 мА
  определяется по меткам AI_TChamber/AI_HChamber;
- INIT — отдельная программа однократного запуска (без IF M8002);
  L02_SET_IP перенесён в MAIN (кнопка «Применить IP»);
- автосброс тревог ОСТАВЛЕН (по ТЗ §8.5);
- РЕСТРУКТУРИЗАЦИЯ: ФБ `FB_IO`, `FB_ALARMS`, `FB_PROCESS`, `FB_ACTUATORS`
  удалены — их код вставлен напрямую в программы `PRG_ROUTINE`
  (рутины: AI + тревоги + вызов `FB_LIGHT`) и `PRG_MAIN`
  (бизнес-логика: автомат + приводы). `FB_LIGHT` остался единственным ФБ.
  Порядок задач: PRG_ROUTINE → PRG_MAIN (сохраняет прежнюю семантику
  FB_IO→FB_ALARMS→FB_LIGHT→FB_PROCESS→FB_ACTUATORS);
- `EI(TRUE);` добавлена первой строкой в каждую программу (PRG_MAIN,
  PRG_ROUTINE, INIT) — разрешение прерываний; `TCO_TICKER_50` из кода
  проекта убран (тикер настроен в отдельной программе TimeControl);
- AI_* ПЕРЕВЕДЕНЫ В REAL (IO.csv: D0–D15, по 2 слова на значение): выходы
  SCALE_AI/L02_SCALE_AI (INT, ×10) через новую функцию `FLT10` (INT→REAL,
  числовое значение сохраняется) → глобальные `AI_*` для HMI-графиков.
  Логика и пороги (×10) не менялись; `AI_RAW_*` остались INT (обрыв 4-20 мА).
