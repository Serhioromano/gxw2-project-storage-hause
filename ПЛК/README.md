# Проект ПЛК — автоматизация камеры овощехранилища (COOLMAY-L02 / GX Works 2)

Один проект заливается в 10 однотипных шкафов **ШУК.260726** (10 камер).
Отличия между камерами (если появятся) выносятся в настройки HMI.

Источники истины:
- план разработки: `plnas/план_разработки.md` (этапы, POUs, карта регистров);
- ТЗ v1.1: `Ссылки/тз_финальное.md`;
- карта адресов: `Ссылки/плк.txt`, привязка меток — `ПЛК/IO.csv`;
- библиотеки: `Ссылки/AlarmManagerV203.md`, `Ссылки/Modbus.EN.md`, `Ссылки/UtilsV3.md`.

---

## 1. Структура файлов

| Файл | POU / назначение |
|---|---|
| `ПЛК/IO.csv` | Глобальные метки I/O (X/Y + датчики `AI_f*` REAL, D0–D15 + сырые `AI_i*` INT, D8032/D8033) — импортировать первым (уже в репозитории) |
| `ПЛК/GVL.csv` | Глобальные переменные (энергонезависимые D500+/M500+): настройки (D500–D515), IP (D520–D523), статусы (D530–D535), упаковка тревог (D550–D551), команды/флаги (M500–M525, M550–M551). Масштабированные значения датчиков — в `IO.csv` (метки `AI_f*`, REAL, D0–D15) |
| `ПЛК/src/PRG_MAIN.st` + `PRG_MAIN.csv` | **MAIN** — программа, **бизнес-логика**: код бывших ФБ `FB_PROCESS` + `FB_ACTUATORS` вставлен напрямую и объединён (автомат Авто 0/100/200/300/400 + приводы: вентиляторы, клапаны, подогрев, Y00; синхронизация с X20 в рециркуляции) |
| `ПЛК/src/PRG_ROUTINE.st` + `PRG_ROUTINE.csv` | **PRG_ROUTINE** — программа рутин: код бывших ФБ `FB_IO` + `FB_ALARMS` вставлен напрямую (масштабирование 7 AI → FLT10 → REAL `AI_f*` для HMI, коррекции, обрывы; AM_SET ×28, AM_HAS_ALARM / AM_IS_BLOCK, AM_PACK, сброс/автосброс) + вызов ФБ `FB_LIGHT` |
| `ПЛК/src/FLT10.st` + `FLT10.csv` | **FLT10** (FUN) — конвертация INT → REAL (масштаб ×10 сохраняется, деление на 10 — на HMI); вызывается в PRG_ROUTINE для назначения `AI_f*` |
| `ПЛК/src/PRG_INIT.st` + `PRG_INIT.csv` | **INIT** — отдельная программа, запускается ОДИН РАЗ при старте (задача на M8002): настройки по умолчанию, AM_INIT (28 тревог), (задел) Modbus |
| `ПЛК/src/FB_LIGHT.st` + `FB_LIGHT.csv` | **FB_LIGHT** (FB) — единственный оставшийся ФБ проекта: выбор режима по переключателю, световая колонна (M8013 — мигание); вызывается из PRG_ROUTINE |

> **HMI (TK8100)** читает входы/выходы (X/Y) и регистры (D/M) напрямую —
> отдельный блок статусов в ПЛК не требуется (после ревью удалён).

Формат CSV — **UTF-16 LE с BOM**, таб-разделитель, все поля в кавычках
(формат экспорта GX Works 2 Label Editor). `.st` — код без `VAR...END_VAR`
(переменные — только в CSV).

> **Именование:** глобальные переменные — camelCase с префиксами
> (`DI_ModeAuto`, `DO_FanH1`, `AI_fTChamber`, `AI_iRawTChamber`,
> `g_iIntensity`, `g_xCmdFanH1`).
> Метки аналоговых входов `AI_*` несут суффикс типа: `AI_f*` — REAL (float),
> `AI_i*` — INT (сырые значения).
> В ВЕРХНЕМ регистре — только константы (библиотечные `AM_ERROR`,
> `STYPE_PT100`, `IP_PLC_IP` и т.п.). При переимпорте `IO.csv` в GX Works 2
> старые метки (`DI_MODE_AUTO` и др.) не удалять автоматически — удалить
> вручную или импортировать в чистый проект.

## 2. Сборка проекта в GX Works 2 (порядок)

1. **Новый проект**: серия FX3G/FX3U (COOLMAY-L02, совместим с FX3G), язык IEC.
2. **Настройки проекта → устройства (Device allocation)** — увеличить лимиты
   автоматически назначаемых устройств (требование AlarmManager V203):
   - D-регистры: **+1400**;
   - M-регистры: **+2000**.
3. **Установить библиотеки** (менеджер библиотек):
   TimeControl V2, AlarmManager V203, Modbus V1.5, Utils V3.
4. **TimeControl V2** — настроить тикер **TCO_TICKER_50** (50 мс). Тикер
   работает в отдельной программе TimeControl и из кода проекта НЕ вызывается.
5. **Label Editor → Import**: `IO.csv` (глобальные метки I/O), затем `GVL.csv`
   (глобальные переменные).
6. **Создать POUs**:
   - `MAIN` — тип Program (бизнес-логика);
   - `PRG_ROUTINE` — тип Program (рутины);
   - `INIT` — тип Program; назначить в задачу так, чтобы запускался
     **один раз** при старте (первый скан / M8002). Если задача циклическая —
     вернуть обёртку `IF M8002` в теле INIT (см. комментарий в `PRG_INIT.st`);
   - `FB_LIGHT` — тип Function Block (единственный ФБ проекта).
7. Для каждого POU: **Label Editor → Import** соответствующий `src/<pou>.csv`,
   затем вставить тело из `src/<pou>.st` в редактор ST.
8. Скомпилировать (F4). Проверить: `AM_ALARMS_NUM = 28`, ошибок связывания нет.

> **Порядок выполнения программ в задаче:** `PRG_ROUTINE` → `PRG_MAIN`
> (рутины: данные → тревоги → колонна — до бизнес-логики). Этот порядок
> совпадает с прежней последовательностью вызовов ФБ
> FB_IO → FB_ALARMS → FB_LIGHT → FB_PROCESS → FB_ACTUATORS, поэтому
> межскановые зависимости (g_iModeCoarse в FB_LIGHT, DO_* в тревогах)
> сохраняют прежнюю семантику.

> **ВАЖНО про CSV**: локальные метки программ/ФБ — в `src/<pou>.csv`
> (7 колонок); глобальные метки I/O — в `ПЛК/IO.csv` (11 колонок, метки
> I/O) и `ПЛК/GVL.csv`. Импортируются в разные места проекта
> (Label Editor: глобальные vs локальные) и не конфликтуют.

---

> Глобальные переменные (настройки, статусы, команды) размещены в
> **энергонезависимой области** (EEPROM): **D500+** и **M500+** — значения
> сохраняются при отключении питания. Диапазоны: настройки D500–D515,
> IP D520–D523, статусы D530–D535, упаковка тревог D550–D551,
> команды/флаги M500–M525, M550–M551.

## 3. Карта регистров (кратко, полная — в `GVL.csv`)

| Диапазон | Назначение |
|---|---|
| D0–D15 | **Масштабированные значения датчиков, REAL** (метки `AI_f*` из IO.csv, по 2 слова на значение): D0–D1 = t улицы, D2–D3 = t камеры, D4–D5 = влажность, D6–D7…D12–D13 = t продукта 1–4, D14–D15 = средняя t продукта. Числовое значение — в масштабе ×10 (например, 245.0 = 24.5 °C); деление на 10 для отображения — на панели HMI |
| D500–D515 | Настройки HMI: D500–D510 — интенсивность, пределы t улицы, подогрев, задержки, пределы t°/влажн.; D511–D515 — коррекция датчиков t (улица 0-10 В + щупы Pt100 1–4), °C×10. Автосброс тревог — флаг `g_xAutoReset` (M525) |
| D520–D523 | IP-адрес ПЛК (октеты 1–4) |
| D530 | `g_iModeDisp`: 0=Выкл, 1=Рециркуляция, 2=Аспирация, 3=Продувка |
| D531 | `g_iRecircLeft` — отсчёт рециркуляции, мин |
| D532 | `g_iAspLeft` — отсчёт аспирации, с |
| D533 | Кол-во активных тревог |
| D534 | `g_iStep` — состояние автомата (0/100/200/300/400) |
| D535 | `g_iModeCoarse` — грубый режим по переключателю |
| D550–D551 | Упакованные тревоги (AM_PACK): D550 = биты 0–15, D551 = биты 16–27 |
| D600–D800 | Буфер Modbus (задел для диспетчеризации/PUSH) |
| M500–M505 | Команды напорных вентиляторов 1–6 |
| M506–M509 | Команды разгонных вентиляторов 1–4 |
| M510–M515 | Команды клапанов (приток1,2 / сброс1,2 / рециркуляция1,2) |
| M516–M519 | Команды подогрева заслонок |
| M520 | Команда Y00 «Остановить холод» |
| M521 | Ручная аспирация выполняется |
| M522 | Кнопка HMI «Ручная аспирация» (фронт) |
| M523 | Кнопка HMI «Сброс тревог» (фронт) |
| M524 | Кнопка HMI «Применить IP» (фронт) |
| M525 | `g_xAutoReset` — автосброс тревог (TRUE=вкл, FALSE=выкл) |
| M550–M551 | `g_xAnyAlarm` / `g_xAnyBlock` (AM_HAS_ALARM / AM_IS_BLOCK) |

> Статусы охладителя/увлажнителя (X20/X21), Y00 и состояние вентиляторов/
> клапанов (Y02–Y31) HMI читает напрямую с физических входов/выходов —
> дублирующих D-регистров в проекте нет.

## 4. Тревоги (28, AlarmManager V203)

| ID | Тревога | Задержка | Защёлка | Severity |
|---|---|---|---|---|
| 0 | Реле контроля фаз (X02) | 0 с | нет | Error, xLock |
| 1–6 | Клапан не открылся | 60 с | нет | Warning |
| 7–12 | Нет потока, напорный вент. | 30 с | нет | Error |
| 13–18 | Пускатель напорного не замкнулся | 3 с | **да** (ручной сброс) | Error |
| 19–22 | Обрыв Pt100 щуп 1–4 | 3 с | нет | Warning |
| 23 | Обрыв датчика улицы (0-10 В) | 3 с | нет | Warning |
| 24–25 | Обрыв 4-20 мА ПВТ110 | 3 с | нет | Warning |
| 26 | t продукта выше макс. | 5 с | нет | Error |
| 27 | Влажность ниже мин. | 5 с | нет | Error |

Защёлки (13–18) снимаются кнопкой сброса на экране тревог HMI (M523).
Автосброс (всех, включая защёлки) — по настройке `g_xAutoReset` (по умолчанию
выключен) через `g_iAutoResetDelay` минут.

## 5. Примечания и проверки при сборке/пуске

1. **TCO_TICKER_50** — тикер TimeControl V2 настроен в отдельной программе
   TimeControl; из кода проекта не вызывается. Проверить на этапе сборки.
2. **Полярности входов** (концевики клапанов, РД-ДД200 — контакт НЗ) приняты:
   «не открыт»/«нет потока» = вход **1**. Подтвердить электриками при пуске.
3. **M8013/M8014** — тактовые генераторы 1 с / 1 мин. На COOLMAY-L02
   (FX3G-совместимый) присутствуют; при отсутствии M8014 заменить тик
   рециркуляции на TON 60 с.
4. **IP-адреса ПЛК** задаются с HMI (D520–D523) и применяются кнопкой
   «Применить IP» (M524) или при включении (L02_SET_IP в MAIN).
5. **Modbus** для диспетчеризации/PUSH — задел, отключён (комментарий в `PRG_INIT.st`).
6. Значения температуры — в **°C×10** (например, 245 = 24.5 °C), влажность —
   в **%×10** (например, 850 = 85.0 %). Коррекция датчиков t (D111–D115) — тоже °C×10.
7. **INIT — отдельная программа**: запускается один раз при старте; при
   циклической задаче вернуть обёртку `IF M8002` (иначе настройки и AM_INIT
   будут выполняться каждый скан).
8. **EI(TRUE);** — первая строка каждой программы (PRG_MAIN, PRG_ROUTINE,
   INIT): разрешение прерываний ПЛК. FB_LIGHT — ФБ, вызова EI не требует.
9. **FLT10 / REAL**: масштабированные значения датчиков (`AI_f*`) — REAL
   в масштабе ×10 (D0–D15, по 2 слова; функция FLT10 = INT→REAL без изменения
   числового значения). Обрывы host-датчиков (тревоги 23–25) определяются
   по `fbScaleHost.ErrWire` (SCALE_AI) сразу после масштабирования;
   `AI_iRawTChamber`/`AI_iRawHChamber` (INT) остались как сырые коды.
   Для отображения в натуральных единицах (°C, %) панель делит на 10.
