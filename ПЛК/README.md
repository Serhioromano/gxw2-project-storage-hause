# Проект ПЛК — автоматизация камеры овощехранилища (COOLMAY-L02 / GX Works 2)

Один проект заливается в 10 однотипных шкафов **ШУК.260726** (10 камер).
Отличия между камерами (если появятся) выносятся в настройки HMI.

Источники истины:
- план разработки: `plnas/план_разработки.md` (этапы, POUs, карта регистров);
- ТЗ v1.1: `Ссылки/тз_финальное.md`;
- карта адресов: `Ссылки/плк.txt`, привязка меток — `ПЛК/IO.csv`;
- библиотеки (в общем репозитории coolmay): `#Общее/coolmay/gxw2-libraries/libraries/AlarmManager/AlarmManager.md (V212)`, `#Общее/coolmay/gxw2-libraries/libraries/ModbusDriver/Modbus.md`, `#Общее/coolmay/gxw2-libraries/libraries/Utils/Utils.md`, `#Общее/coolmay/gxw2-libraries/libraries/TimeControl/TimeControl.md`.

## 1. Структура файлов

| Файл | POU / назначение |
|---|---|
| `ПЛК/IO.csv` | Глобальные метки I/O (X/Y + датчики `AI_f*` REAL, D0–D15 + сырые `AI_i*` INT, D8032/D8033) — импортировать первым (уже в репозитории) |
| `ПЛК/GVL.csv` | Глобальные переменные (энергонезависимые D500+/M500+): настройки (D500–D517), состояния вентиляторов (D520–D529), статусы (D530–D535), упаковка тревог (D550–D552), команды/флаги (M500–M526, M550–M551). Масштабированные значения датчиков — в `IO.csv` (метки `AI_f*`, REAL, D0–D15, натуральные единицы) |
| `ПЛК/src/PRG_MAIN.st` + `PRG_MAIN.csv` | **MAIN** — программа, **бизнес-логика**: код бывших ФБ `FB_PROCESS` + `FB_ACTUATORS` вставлен напрямую и объединён (автомат 0/2/50/100/200/210/300: 0=СБРОС→2=ОЖИДАНИЕ, 50=ПРОДУВКА, 100–300=Авто; приводы: вентиляторы, клапаны, подогрев, Y00; вентиляторы следуют за охладителем X03 в рециркуляции) |
| `ПЛК/src/PRG_ROUTINE.st` + `PRG_ROUTINE.csv` | **PRG_ROUTINE** — программа рутин: код бывших ФБ `FB_IO` + `FB_ALARMS` вставлен напрямую (масштабирование 7 AI → FLT10 → REAL `AI_f*` для HMI, коррекции, обрывы; FB_AM_SET ×34, FB_AM_HAS_ALARMS / FB_AM_IS_BLOCK, FB_AM_PACK_ALARMS, сброс/автосброс) + вызов ФБ `FB_LIGHT` + **Modbus slave порт 2** (RS-485, xInit = M8002 OR `g_xMbApply`) |
| `ПЛК/src/FLT10.st` + `FLT10.csv` | **FLT10** (FUN) — конвертация INT → REAL с делением на 10 (натуральные единицы °C, %); вызывается в PRG_ROUTINE для назначения `AI_f*` и для порогов в сравнениях |
| `ПЛК/src/PRG_INIT.st` + `PRG_INIT.csv` | **INIT** — отдельная программа, запускается ОДИН РАЗ при старте (задача на M8002): настройки по умолчанию, FB_AM_INIT (34 тревоги) |
| `ПЛК/src/FB_LIGHT.st` + `FB_LIGHT.csv` | **FB_LIGHT** (FB) — единственный оставшийся ФБ проекта: выбор режима по переключателю, световая колонна (M8013 — мигание); вызывается из PRG_ROUTINE |

> **HMI (TK8100)** читает входы/выходы (X/Y) и регистры (D/M) напрямую —
> отдельный блок статусов в ПЛК не требуется (после ревью удалён).

Формат CSV — **UTF-16 LE с BOM**, таб-разделитель, все поля в кавычках
(формат экспорта GX Works 2 Label Editor). `.st` — код без `VAR...END_VAR`
(переменные — только в CSV).

> **Именование:** глобальные переменные — camelCase с префиксами
> (`DI_ModeAuto`, `DO_FanH1`, `AI_fTChamber`, `AI_iRawTChamber`,
> `g_iIntensity`, `g_xCmdFanH1`).
> Метки аналоговых входов `AI_*` несут суффикс типа: `AI_f*` — REAL (float),
> `AI_i*` — INT (сырые значения).
> В ВЕРХНЕМ регистре — только константы (библиотечные `c_AM_ERROR`,
> `STYPE_PT100`, `IP_PLC_IP` и т.п.). При переимпорте `IO.csv` в GX Works 2
> старые метки (`DI_MODE_AUTO` и др.) не удалять автоматически — удалить
> вручную или импортировать в чистый проект.

## 2. Сборка проекта в GX Works 2 (порядок)

1. **Новый проект**: серия FX3G/FX3U (COOLMAY-L02, совместим с FX3G), язык IEC.
2. **Настройки проекта → устройства (Device allocation)** — увеличить лимиты
   автоматически назначаемых устройств (требование AlarmManager V212):
   - D-регистры: **+1400**;
   - M-регистры: **+2000**.
3. **Установить библиотеки** (менеджер библиотек):
   TimeControl V2, AlarmManager V212, Modbus V1.5, Utils V3.
4. **TimeControl V2** — настроить тикер **TCO_TICKER_50** (50 мс). Тикер
   работает в отдельной программе TimeControl и из кода проекта НЕ вызывается.
5. **Label Editor → Import**: `IO.csv` (глобальные метки I/O), затем `GVL.csv`
   (глобальные переменные).
6. **Создать POUs**:
   - `MAIN` — тип Program (бизнес-логика);
   - `PRG_ROUTINE` — тип Program (рутины);
   - `INIT` — тип Program; назначить в задачу так, чтобы запускался
     **один раз** при старте (первый скан / M8002). Если задача циклическая —
     вернуть обёртку `IF M8002` в теле INIT (см. комментарий в `PRG_INIT.st`);
   - `FB_LIGHT` — тип Function Block (единственный ФБ проекта).
7. Для каждого POU: **Label Editor → Import** соответствующий `src/<pou>.csv`,
   затем вставить тело из `src/<pou>.st` в редактор ST.
8. Скомпилировать (F4). Проверить: `c_AM_ALARMS_NUM = 33` (хранилище `AM_ALARMS`/`AM_EVENTS` объявлено в GVL.csv), ошибок связывания нет.

> **Порядок выполнения программ в задаче:** `PRG_ROUTINE` → `PRG_MAIN`
> (рутины: данные → тревоги → колонна — до бизнес-логики). Этот порядок
> совпадает с прежней последовательностью вызовов ФБ
> FB_IO → FB_ALARMS → FB_LIGHT → FB_PROCESS → FB_ACTUATORS, поэтому
> межскановые зависимости (g_iModeCoarse в FB_LIGHT, DO_* в тревогах)
> сохраняют прежнюю семантику.

> **ВАЖНО про CSV**: локальные метки программ/ФБ — в `src/<pou>.csv`
> (7 колонок); глобальные метки I/O — в `ПЛК/IO.csv` (11 колонок, метки
> I/O) и `ПЛК/GVL.csv`. Импортируются в разные места проекта
> (Label Editor: глобальные vs локальные) и не конфликтуют.

---

> Глобальные переменные (настройки, статусы, команды) размещены в
> **энергонезависимой области** (EEPROM): **D500+** и **M500+** — значения
> сохраняются при отключении питания. Диапазоны: настройки D500–D517,
> состояния вентиляторов D520–D529, статусы D530–D535, упаковка тревог D550–D552,
> команды/флаги M500–M526, M550–M551.

## 4. Тревоги (34, AlarmManager V212)

| ID | Тревога | Задержка | Защёлка | Severity |
|---|---|---|---|---|
| 0 | Реле контроля фаз (X02) | 0 с | нет | Error, xLock |
| 1–6 | Клапан не открылся | g_iValveTime (с) | нет | Warning |
| 7–12 | Нет потока, напорный вент. | 30 с | нет | Error |
| 13–18 | Пускатель напорного не замкнулся | 3 с | **да** (ручной сброс) | Error |
| 19–22 | Обрыв Pt100 щуп 1–4 | 3 с | нет | Warning |
| 23 | Обрыв датчика улицы (0-10 В) | 3 с | нет | Warning |
| 24–25 | Обрыв 4-20 мА ПВТ110 | 3 с | нет | Warning |
| 26 | t продукта выше макс. | 5 с | нет | Error |
| 27 | Влажность ниже мин. | 5 с | нет | Error |
| 28–33 | Клапан не закрылся | g_iValveTime (с) | нет | Warning |

Защёлки (13–18) снимаются кнопкой сброса на экране тревог HMI (M523).
Автосброс (всех, включая защёлки) — по настройке `g_xAutoReset` (по умолчанию
выключен) через `g_iAutoResetDelay` минут.

## 5. Примечания и проверки при сборке/пуске

1. **TCO_TICKER_50** — тикер TimeControl V2 настроен в отдельной программе
   TimeControl; из кода проекта не вызывается. Проверить на этапе сборки.
2. **Полярности входов**: РД-ДД200 — контакт НЗ («нет потока» = вход **1**);
   концевики клапанов «закрыт» — контакт НО («закрыт» = вход **1**); концевики
   «открыт» — по обновлённому `Ссылки/плк.txt` также НО, но тревоги 1–6 всё
   ещё закодированы под прежнюю НЗ-полярность — подтвердить и привести к НО
   при пуске (см. `plnas/вопросы_заказчику.md` §1.3).
3. **M8013/M8014** — тактовые генераторы 1 с / 1 мин. На COOLMAY-L02
   (FX3G-совместимый) присутствуют; при отсутствии M8014 заменить тик
   рециркуляции на TON 60 с.
4. **IP-адрес ПЛК**: настройка IP с HMI УПРАЗДНЕНА — регистры D520–D523
   (бывшие октеты IP) теперь заняты состояниями вентиляторов
   `g_iFun1State..g_iFun4State`; кнопки «Применить IP» и вызова L02_SET_IP
   в проекте больше нет.
5. **Modbus slave** (порт 2, RS-485) — АКТИВЕН: с HMI задаётся только адрес
   `g_iMbAddr` (D516, 1..247); чётность/стоп-бит/скорость зафиксированы в коде
   как 9600 8N1 (в PRG_ROUTINE: `MB_PARITY_NONE`, `MB_STOPBIT_1`,
   `MB_BPS_9600`). Инициализация — по `M8002 OR g_xMbApply` (первый скан или
   кнопка HMI M526). Регистры чётности/стоп-бита/скорости (бывшие D517–D519)
   УДАЛЕНЫ: D517 теперь занят `g_iValveTime`, D518 — `g_iProgress`
   (прогресс фазы 0..100 %), D519 — `g_iLeftTime` (минут осталось до конца
   фазы; оба заполняются ПЛК в режиме «Авто» для рециркуляции и аспирации).
6. Настройки-пороги и сырые INT-значения датчиков — в **°C×10**
   (например, 245 = 24.5 °C) и **%×10** (например, 850 = 85.0 %).
   Коррекция датчиков t (D511–D515) — тоже °C×10. Масштабированные
   REAL-значения `AI_f*` (D0–D15) — уже в натуральных единицах (°C, %),
   панель читает их напрямую (без деления на 10).
7. **INIT — отдельная программа**: запускается один раз при старте; при
   циклической задаче вернуть обёртку `IF M8002` (иначе настройки и FB_AM_INIT
   будут выполняться каждый скан).
8. **EI(TRUE);** — первая строка каждой программы (PRG_MAIN, PRG_ROUTINE,
   INIT): разрешение прерываний ПЛК. FB_LIGHT — ФБ, вызова EI не требует.
9. **FLT10 / REAL**: функция `FLT10` = `INT_TO_REAL(x) / 10.0` — переводит
   масштабированное INT-значение (×10) в REAL в НАТУРАЛЬНЫХ единицах (°C, %).
   Глобальные метки `AI_f*` (IO.csv, D0–D15, по 2 слова) хранят именно эти
   натуральные значения — панель читает их напрямую, БЕЗ деления на 10.
   Обрывы host-датчиков (тревоги 23–25) определяются по `fbScaleHost.ErrWire`
   (SCALE_AI) сразу после масштабирования; `AI_iRawTChamber`/`AI_iRawHChamber`
   (INT) остались как сырые коды.

   СРАВНЕНИЯ (тип!): в GX Works 2 IEC ST нет неявного REAL↔INT в операциях
   сравнения, поэтому пороги-настройки (INT, масштаб ×10) в сравнениях с
   REAL-значениями AI_f* (натуральные единицы) преобразуются функцией FLT10
   (t улицы в PRG_MAIN, влажность в PRG_ROUTINE №27). Щупы продукта (L02-RTD) —
   модуль выдаёт готовую температуру °C×10 в R23700…R23703 (INT), тревоги 19–22
   и 26 сравнивают эти регистры напрямую с порогами (INT ↔ INT) — без перевода в REAL.
10. **Профили интенсивности** `astIntens[0..2]` (структура `ST_INTENS` с полями
    `RECIRC`/`ASPER`) задаются в GVL.csv и настраиваются с HMI: Слабо = 1200/5,
    Нормально = 600/5, Интенсивно = 300/5 (мин рециркуляции / мин аспирации).
    С HMI задаётся индекс `g_iIntensity` (D500). На этих длительностях строится
    прогресс фазы `g_iProgress` (D518) и обратный отсчёт `g_iLeftTime` (D519);
    прогрев клапанов — по `g_iPreheatTime` (D504).
11. **Вентиляторы — каскадный пуск**: напорные/разгонные включаются по цепочке
    с интервалом 2 с (FanH1 — 2 с, FanH2 — 4 с, … FanR4 — 20 с; каждый — свой
    TON), выключаются сразу, TOF держит выход ещё 3 с. В Выключено
    (`g_xModeManual` = TRUE) каскад принудительно гасится (`AND NOT
    g_xModeManual`), а TOF питается ТОЛЬКО от `fbTON*.Q`. Ветки прямого
    замыкания в TOF нет — иначе при переключении Продувка/Авто → Выключено
    ещё не включённые вентиляторы кратковременно включались бы все разом
    (гонка: команды `g_xCmdFan*` в скане перехода ещё TRUE, `g_xModeManual`
    уже TRUE). `g_xModeManual` (M524) остаётся только для HMI-индикации и
    гашения каскада.
